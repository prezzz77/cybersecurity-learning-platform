程式與資料

Programs & Data

認識程式指令與資料的分工，追蹤輸入如何經過程式處理成輸出，並了解程式本身也可以作為資料保存與處理。

學完這一課，你可以

  • 分辨程式中的指令和程式要處理的資料。
  • 說明輸入如何經過程式處理後成為輸出。
  • 用例子說明程式在執行時是指令，也可以被其他程式當作資料讀取。

01 / 資料

電腦需要處理的內容是資料

資料（data）是程式可以讀取、保存或運算的內容，例如數字、文字、圖片檔案，或表單中輸入的姓名。資料本身不會告訴 CPU 要進行什麼操作；程式會決定如何使用它。

例如，數字 8 可以是購物數量、溫度或運算中的一個值。電腦只處理資料所代表的內容，資料的用途要由程式和使用情境決定。

02 / 指令

指令描述要執行的操作

指令（instruction）是要求電腦執行一項操作的描述，例如「相加」、「比較」或「把結果保存」。CPU 執行指令，資料則是指令可能讀取或修改的內容。

如果指令要求「把輸入的數字加 3」，指令說明操作，輸入的數字是資料。完成後產生的新數字也是資料。

Program 一組操作指令→ CPU 執行指令← Data 指令處理的內容

03 / 程式

程式把操作排成可執行的步驟

程式（program）是一組有順序的操作指令，告訴電腦要做什麼。計算程式可以先讀取數字，再依指定方式運算，最後提供結果。

CPU 依照程式指令工作，資料則是程式要處理的內容。因此，同一個資料值可以交給不同程式或不同指令處理，產生不同結果。

04 / 輸入與輸出

資料如何從輸入變成輸出？

輸入（input）是程式收到的資料，例如使用者輸入的數字。輸出（output）是程式處理後提供的結果，例如螢幕顯示的答案或保存的檔案。

處理（processing）是程式依照指令讀取或改變資料的工作。整個流程可以簡化為：

INPUT輸入數字 8
→
PROGRAM程式加上 3 的指令
→
PROCESSING處理CPU 執行加法
→
OUTPUT輸出結果 11

05 / 記憶體

執行中的程式和資料會放進記憶體

記憶體（memory）是在程式執行期間暫時存放指令和資料的空間。程式載入並開始執行時，它的指令和目前處理的資料會放在記憶體中，讓 CPU 能取用。

例如使用者輸入 8 之後，程式指令「加上 3」和輸入值都會供執行中的程式使用。CPU 依照指令處理輸入資料，程式再使用計算結果。RAM 是這類執行期間記憶體的常見例子。

06 / 程式也能是資料

同一個程式，會依情境扮演不同角色

程式執行時，它提供 CPU 要執行的指令。但在執行之前，程式通常以檔案形式保存在 SSD 或 HDD 中。這個檔案由位元組組成，可以被複製、保存，也可以被其他程式讀取；在這些情況下，程式檔案就是其他程式處理的資料。

例如文字編輯器可以讀取程式碼檔案並顯示文字。對文字編輯器來說，檔案是它要讀取和顯示的資料；當電腦載入並執行另一個程式時，其中的操作描述則會由 CPU 當作指令執行。

所以「程式」和「資料」不是永遠固定的兩種檔案。要看目前是哪個程式在處理它，以及它在這個情境中的用途。

兩種情境

程式正在執行：它的指令讓 CPU 知道要做什麼。程式檔案正被複製或由編輯器讀取：檔案內容是另一個程式要處理的資料。

09 / 與資安的關係

程式需要分辨指令和輸入資料

使用者輸入通常是不受程式控制的內容，稱為不可信任輸入（untrusted input）。程式應該檢查輸入是否符合預期，這類檢查稱為輸入驗證（input validation）。

如果程式把本來應該當作資料的內容錯誤地解讀成操作指令，就可能出現注入（injection）類問題。這裡先建立「程式必須正確區分程式指令和資料」的概念，後續 Web Security 才會說明具體漏洞與防護。

你已經知道

程式提供 CPU 操作步驟，資料是程式要處理的內容。輸入經過程式處理後形成輸出；程式檔案也能被其他程式當作資料讀取。
